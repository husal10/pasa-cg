# Max-pressure signal control under detector faults

SUMO simulation code, raw results and analysis scripts for two studies of max-pressure traffic signal control with faulty detectors:

1. **Detector-fault study.** Which detector faults (dead, stuck, noisy, intermittent, drifting and others) harm max-pressure, whether combining the readings of opposing approaches helps, and what the minimum-green and maximum-red guards cost. Scripts: `analysis/fault_study/`.
2. **PASA-CG.** A filter that checks each detector reading against the signal phase it is served by, replaces only the readings that fail, and needs no fault diagnosis and no training; compared with the field responses to a failed detector. Scripts: `analysis/pasa_cg/`.

The papers that use this code are listed under [Papers](#papers) once they are published. Each paper is tied to a tagged release of this repository, archived on Zenodo with its own DOI.

## Contents

| Folder | What it holds |
|---|---|
| `pasa_cg/` | Simulation package: network builder, fault injection, controllers, PASA-CG, sweep runner, checks |
| `pasa_cg/cologne1/` | Cologne1 scenario files (third-party, see Licences) |
| `data/` | SUMO network and route files used by the sweeps (one folder per run window) |
| `runs/` | Windows batch files and the generator that launched the sweeps |
| `results/` | Raw results: one `all_results.json` per scenario, plus the per-cell files written during the runs |
| `tables/` | Per-episode tables built from `results/` (inputs to the analysis scripts) |
| `analysis/` | Statistics and figure scripts: `fault_study/` and `pasa_cg/` |
| `tools/` | Episode audit script used after each sweep |

| Result folder | Sweep |
|---|---|
| `results/results_v2` | Main grid sweep (two demand profiles, three demand levels, four fault patterns) |
| `results/results_ablation` | PASA-CG ablations (symmetric grid, medium and high demand) |
| `results/results_emis` | Emission runs (key cells, SUMO emission device on) |
| `results/results_c1` | Cologne1 main sweep |
| `results/results_rev` | Additional sweeps: field fallbacks with oracle diagnosis (R1, R8), guards (R2, R3, R8), planning error (R4), thresholds (R5), extra fault types and fault windows (R6), clip exemption (R7), diagnosis delay (R9) |

## Requirements

- SUMO 1.24 (the results were produced with Eclipse SUMO 1.24.0 on Windows 11), with `SUMO_HOME` set so that `traci` and `sumolib` can be imported
- Python 3.10 or later
- `pip install -r requirements.txt`

## Running a scenario

```
python -m pasa_cg.main verify --net-dir data/net_sym
python -m pasa_cg.main run-sweep --network grid2x2 --demand-profile symmetric ^
    --demand-level medium --fault-pattern phase_symmetric --fault-severity high ^
    --controllers std_mp_q pasa_max_mp pasa_cg_mp --fault-modes NONE HZ ^
    --n-seeds 10 --net-dir data/net_sym --output-dir results_new/example
python -m pasa_cg.main demo --controller pasa_cg_mp --fault HZ --fault-pattern phase_symmetric
```

(`^` continues a line in the Windows command prompt; use `\` in bash.) The full option list is in `python -m pasa_cg.main run-sweep --help`. Every `all_results.json` records the settings it was run with, so any scenario in `results/` can be rerun with the same options. The commands for the additional sweeps are in `runs/run_rev_w*.bat` (generated by `runs/make_bats.py`). Finished cells are skipped, so an interrupted sweep can be restarted.

## Reproducing the tables and figures

From the repository root:

```
python analysis/pasa_cg/analyse.py results tables
python analysis/extract_rev_episodes.py results/results_rev tables/rev_episodes.csv
python analysis/extract_c1_episodes.py results/results_c1 tables/c1_episodes.csv

cd tables
python ../analysis/pasa_cg/analyse_rev.py
python ../analysis/pasa_cg/analysis_revision.py . . out_extra
python ../analysis/fault_study/conf_stats.py
python ../analysis/fault_study/conf_figures.py ../figures/fault_study
cd ..

python analysis/pasa_cg/figures_v2.py tables figures/pasa_cg
python analysis/pasa_cg/figures_cologne1.py results figures/pasa_cg tables
python analysis/pasa_cg/figures_sustainability.py results figures/pasa_cg
python analysis/pasa_cg/figures_revision.py tables figures/pasa_cg
python analysis/pasa_cg/fig_pasa_cg_flow.py figures/pasa_cg
python analysis/fault_study/fig_conf_network.py data/net_sym/grid2x2.net.xml figures/fault_study
```

| Study | Item | Script | Output |
|---|---|---|---|
| Fault study | Network and fault patterns | `analysis/fault_study/fig_conf_network.py` | `fig_conf_network` |
| Fault study | Fault map, aggregation, guards | `analysis/fault_study/conf_figures.py` | `fig_conf_faultmap`, `fig_conf_aggregation`, `fig_conf_guards` |
| Fault study | Tables and numbers in the text | `analysis/fault_study/conf_stats.py` | `tables/out_fault_study/F1_*`, `F2_*`, `F3_*` |
| PASA-CG | Main figures | `analysis/pasa_cg/figures_v2.py` | `fig_headline_*`, `fig_heatmap_*`, `fig_ablation`, `fig_detection` |
| PASA-CG | Cologne1 | `analysis/pasa_cg/figures_cologne1.py` | `fig_c1_*`, `c1_tests.csv`, `c1_summary.csv` |
| PASA-CG | Emissions | `analysis/pasa_cg/figures_sustainability.py` | `fig_sus_*`, `sustainability_*.csv` |
| PASA-CG | Guards and diagnosis delay | `analysis/pasa_cg/figures_revision.py` | `fig_rev_guards`, `fig_rev_diagdelay` |
| PASA-CG | Flow chart | `analysis/pasa_cg/fig_pasa_cg_flow.py` | `fig_pasa_cg_flow` |
| PASA-CG | Confirmatory tests, ablation | `analysis/pasa_cg/analyse.py` | `confirmatory_total_delay.csv`, `ablation_total_delay.csv`, `summary_*.csv` |
| PASA-CG | Additional sweeps | `analysis/pasa_cg/analyse_rev.py` | `tables/out/R*.csv` |
| PASA-CG | Tallies, orientation split, CIs, Cologne1 family | `analysis/pasa_cg/analysis_revision.py` | `tables/out_extra/*.csv` |

The primary outcome is network total delay in vehicle-hours, `time_loss * n_trips / 3600` per episode. Seeds are paired across controllers and fault conditions.

## Code versions

Three code versions produced the results. Each `all_results.json` stores a SHA-256 hash of the package source, the SUMO version and the platform under `provenance`. For the public release the package was renamed, the comments, docstrings and console messages were tidied, and an unused plotting module was removed; the simulation code is otherwise unchanged. A test run of the release against the source that produced the last sweeps (hash `485adb78846c...`) gave identical episode results, but the hash of the released source differs from the recorded ones.
